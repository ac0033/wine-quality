# 第四步计划：检验理化指标能否优于验证基线

**状态：待用户评估，未执行。** 本步的完整目的，是判断在现有研究性回归任务和固定数据划分下，11 个理化指标能否使红酒、白酒的 `quality` 预测在验证集上优于第三步训练中位数基线。即使验证结果较好，本步也不宣布生产可用或未来样本效果；最终评估集继续封存。

## 要回答的问题和输入

红酒、白酒分别判断：同一批验证行上，使用理化指标的候选模型相对不使用理化指标的基线，MAE 改善多少，RMSE 是否恶化，结果是否受少数特征组合或少见 `quality` 分值左右？第二步的相关关系只提出检验动机，不作为已经存在预测收益的证据。

只读输入为三份[原始数据](../../../data/)、第一步[数据概况](../../01_数据预处理/1.1_原始数据理解与质量核验/outputs/data_profile.json)、第二步[完整统计](../../02_EDA/2.1_理化指标与quality的探索分析/outputs/eda.json)、第三步[逐行划分表](../../03_数据划分/3.1_预测任务定义_固定划分与验证基线/outputs/split_assignments.csv)、[划分摘要](../../03_数据划分/3.1_预测任务定义_固定划分与验证基线/outputs/split_summary.json)及[验证基线结果](../../03_数据划分/3.1_预测任务定义_固定划分与验证基线/outputs/baseline_validation.json)。执行前后核对这些文件的路径、字节数、SHA256；原始行和既有步骤产物均不覆盖。`quality` 是预测目标；预测时点沿用第三步假设：11 个理化指标已测得，而专家评分未知。实际用途若不满足该顺序，本步停止并重新定义任务。

## 拟执行的比较

1. **锁定输入和比较口径。** 按[逐行划分表](../../03_数据划分/3.1_预测任务定义_固定划分与验证基线/outputs/split_assignments.csv)取红酒、白酒的训练和验证行，核对 6,497 个原始行号无遗漏、同类酒相同特征组合不跨划分，并复算第三步基线。模型输入使用全部 11 个原始理化指标；不使用 `quality`、原始文件行号、特征组合 ID 或划分标签作为输入。初次比较不根据第二步相关系数删选指标。
2. **比较两类预先确定的候选模型。** 每类酒分别训练一个带训练集内标准化的 Ridge 回归模型，作为线性关系的候选；参数固定为 `alpha=1.0`、`fit_intercept=True`。再训练一个随机森林回归模型，检验非线性关系能否带来额外收益；参数固定为 `n_estimators=300`、`min_samples_leaf=5`、`max_features=1.0`、`random_state=20260914`、`n_jobs=1`，其余使用记录在日志中的库版本默认值。两类候选均不用验证集反复调参；标准化只在训练行拟合。候选模型的选择用于覆盖线性与非线性两种假设，不预设哪一种会胜出。
3. **只在固定验证集评价。** 每个候选模型分别对红酒 **331 行**、白酒 **983 行**验证记录输出预测，计算与第三步完全同口径的 MAE、RMSE，并报告相对基线的绝对差。保留逐行预测与误差，按 `quality` 分值报告行数和误差；对少见分值只描述，不凭少量样本下结论。以特征组合为单位有放回重抽样 **2,000 次**，每次带入被抽中组合的全部验证行，对候选与基线的**配对 MAE 差（候选减基线）**取 2.5% 和 97.5% 分位数，固定种子 `20260914`。该区间仅反映当前验证集在此重抽样方式下的波动，不能证明未来泛化。
4. **形成下一步决定。** 分别给出红酒、白酒的全部候选结果，不只报最佳分数。如果某候选的验证 MAE 低于基线、上述配对差区间的上界小于 **0**，且 RMSE 不高于基线，可把它登记为下一步进一步验证的候选；若证据不足或指标冲突，如实报告，不通过更换种子、增试大量参数或打开最终评估集追求好看的结果。验证集上的比较和选择会影响后续估计，最终结论仍需保留最终评估集。

## 产物及用途

新产物仅写入 `steps/04_model_comparison/`：`outputs/model_comparison.json` 保存每类酒的基线、两种候选、参数、MAE/RMSE、差值、区间及按分值的误差；`outputs/validation_predictions.csv` 保存验证行号、候选名称、真值、预测和误差，供独立复核与诊断；`src/compare.py` 复现训练和评价；`checks/verify.py` 与 `checks/verification.json` 从原始 CSV、固定划分和预测表独立重算数据覆盖、指标与差值；`execution.jsonl` 保存输入指纹、依赖版本、参数、运行命令及成功或失败尝试；`report.md` 解释比较结果、证据边界和下一步建议。模型若需保存，只另存于本步目录并登记版本，不修改第三步基线或划分。

## 验收与停止条件

- 输入指纹不变；红酒/白酒训练、验证行数与第三步一致，验证预测对每个候选的每条验证行恰好一条。任一行遗漏、重叠或特征组合跨划分，停止并查因。
- 所有拟合型处理只从本类酒训练行估计；最终评估行不能参与训练、参数选择、预测输出或误差计算。代码、日志、结果和报告均能证明这条边界。
- 独立复核从逐行预测重算每类酒、每个候选的 MAE、RMSE、相对基线差值及按分值行数；主 agent 再从原始 CSV 和实际产物复核关键结果。程序运行成功不等于比较结论成立。
- 如果验证 MAE 没有改善、区间跨越无改善或 RMSE 恶化，保留完整结果并说明冲突；不得将其写成稳定优于基线。若缺少可用依赖或预测时点假设不成立，停止并更新计划，不以临时改变模型范围掩盖问题。

用户同意本计划并安排执行 agent 后才启动第四步。主 agent 对实际产物独立验收并向用户汇报；用户理解且同意后，再决定是否进入下一步。
