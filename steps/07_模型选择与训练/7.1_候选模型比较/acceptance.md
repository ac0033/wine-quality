# 7.1 验收

**结论：执行通过；四个候选满足登记门槛，登记为进入最终评估的候选。** 用户已授权连续完成后续步骤，本验收由主 agent（同一执行者）按计划的验收条款自查，证据全部落在文件里，可以重跑。

## 输入保全

`model_comparison.json` 的 `inputs_before` / `inputs_after` 记录了八份输入（三份原始文件、1.1 的数据概况、2.1 的完整统计、3.1 的划分表、划分摘要、基线结果）的字节数与 SHA256，执行前后一致；`checks/verify.py` 在复核时按当前磁盘文件再对照一次，一致。

## 拟合范围与预测覆盖

- notebook 第 3 格从划分表取行：训练 / 验证 / 最终评估分开，`train`、`valid` 只含对应划分的行，最终评估行只计数（红酒 318、白酒 994），没有进入任何拟合、预测或误差计算；第 4 格的标准化均值、标准差只从训练行估计，两份 `scaler_*.json` 记录 `fitted_on: training rows only`。
- 复核从原始 CSV 重建每条验证行的特征组合 ID，核对预测表的 `feature_group_id` 与真值；每个候选对红酒 331 行、白酒 983 行各恰好一条预测，没有最终评估行、没有非有限预测。

## 指标与区间

- 基线只从训练行重算中位数（两类酒都是 6.0），验证 MAE / RMSE 与 3.1 的 `baseline_validation.json` 在 1e-10 容差内一致。
- 四个候选的 MAE、RMSE、相对基线的差值、按 quality 分值的行数与误差，全部从逐行预测重算一致；各分值行数合计回到 331 / 983。
- 重抽样：有序组合 ID 就是验证集特征组合按字典序（红酒 274、白酒 794 个）；2,000 次每次恰好抽 G 个索引；从索引与逐行误差重算的 2,000 个配对差与 `bootstrap_mae_differences.csv` 逐次一致；线性插值分位数与 `model_comparison.json` 的区间一致。
- 登记判定按门槛重算与文件一致：四个候选 MAE 低于基线、区间上界小于 0、RMSE 不高于基线。

## 故障注入

用内存副本做三处注入，检查器分别拒绝：删掉红酒 Ridge 对第 1 行的预测（覆盖检查失败）、把白酒随机森林一条真值加 1（真值检查失败）、混入一条红酒最终评估行的预测（封存检查失败）。权威产物没有被改写。

## 验收边界

- 这是研究筛选，不是生产收益证明：没有业务成本依据，计划明确不编造有用改善幅度的门槛。
- 四个候选都在验证集上筛出来，后续估计会偏乐观；最终数值以 9.1 在最终评估集上只评一次为准，并须披露最终评估集在 2.1 被全量探索看过。
- 没有做多重比较校正；随机森林与 Ridge 的区间大幅重叠，本步不在两者之间取舍。
- 主 agent 与执行 agent 为同一人，独立性弱于 1.1～3.1 的验收；补偿手段是全部核对都由不依赖 notebook 代码的 `verify.py` 完成并留档。
